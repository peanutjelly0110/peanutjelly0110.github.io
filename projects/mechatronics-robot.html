Autonomous Wall-Following & Ball-Sorting Robot (TI C2000 + Raspberry Pi)

Embedded C • Real-Time Motor Control • Sensor Integration • Autonomous Behaviors • Debugging & Tuning
Mechatronics Embedded C PID Control Systems Integration Autonomy

Overview

As part of a UIUC mechatronics semester project, my team built an autonomous mobile robot that navigated a maze while hugging the right wall. The robot detected colored golf balls (pink and purple), collected them, stored them in separate compartments, and performed a final sorting/drop-off behavior at the end of the course.

Core behaviors
  • Right-wall following (“hug the wall”) navigation through a maze
  • Color-based object detection for two classes (pink vs. purple)
  • Ball pickup and storage in left/right compartments based on color
  • Final sorting/drop-off routine and stop at a designated location

System Architecture

The robot used a dual-board architecture:

  • TI LaunchXL-F28379D (C2000 MCU): real-time motor control, PWM generation, encoder feedback, interrupts/timers, and low-level control loops in embedded C.
  • Raspberry Pi: higher-level logic and sensor integration (e.g., perception/decision logic and coordination of behaviors).
External localization (monitoring)

Reflective marker balls mounted on the robot were tracked by the lab motion-capture system. This provided an external estimate of robot pose (position/orientation) for monitoring and evaluation, not for closed-loop control.

Controls

Wall-following control strategy
  • Implemented PID-based speed/steering behavior to maintain a desired right-wall distance.
  • Used encoder feedback for speed estimation and consistent motion control.
  • Tuned gains empirically to balance stability (no oscillation) and responsiveness (tight turns).

Key engineering trade-off: aggressive gains improved cornering but increased oscillation and wheel slip; conservative gains were stable but slower to correct wall-distance errors.

Sensing & Perception

Distance sensing
  • Used distance measurements to support right-wall following and obstacle proximity handling.
  • Validated sensor readings in the maze and handled noisy measurements via filtering/tuning.
Color-based object detection
  • Detected pink vs. purple golf balls and triggered pickup behavior when a target was observed.
  • Mapped detection outcomes to behavior decisions (pick up + store left/right based on color).

Autonomy & State Machine

The overall behavior was implemented as a finite-state machine (FSM), for example: 

Wall-Follow  →  Detect Ball  →  Approach/Pickup  →  Store (Left/Right)
      ↘_______________________________________________↗
                 Final Sorting / Drop-off → Stop

Debugging & What I Enjoyed

  • Real-time debugging of embedded C code (timing issues, interrupts, sensor noise).
  • Tuning PID and steering logic in a real maze environment with physical constraints.
  • Integrating multiple subsystems until the full end-to-end behavior worked reliably.

What I learned

  • How to split responsibilities between real-time control (MCU) and higher-level autonomy (Linux SBC).
  • How sensor noise and timing affect control performance in physical systems.
  • How to build robust robotics behavior using state machines and incremental testing.
